RNBW lane decode: serial versus lane-parallel A/B
Date: 2026-11-09
Both versions ran `cargo bench --offline --locked --bench files -- file-decode --sample-size 10 --warm-up-time 0.1 --measurement-time 0.15 --noplot --quiet`. Each run analyzed all 175 decode groups across 16 workloads; AVX2 host.
The serial version was measured first. The parallel version decodes independent lanes with Rayon only when lane_count > 1 and raw bytes >= 16 KiB. Codec bytes and token formats are unchanged. Frozen corpus files and deterministic generators kept the same 16 dataset names and byte lengths between runs.

Result: RGBA8 decode improved 1.45x (4.1919 ms to 2.8935 ms); the 16-lane synthetic int8 tensor improved 1.14x (1.8795 ms to 1.6437 ms). Other multi-lane examples were statistically flat at this sample size: shader words 408.94 to 413.60 us and structured records 1.0459 to 1.0565 ms. Single-lane differences are not caused by the parallel branch; treat small shifts as noise.

Correctness: `cargo test --offline --locked` passed after the implementation: 38 library tests, 3 binary tests, 1 deterministic codec mutation fuzz test, and 3 TRNMAP fuzz tests.
