## Method

Hyperfine used `--shell=none --warmup 2 --runs 10`. It launched all three engines (`rnbw`, `plain-ef`, `raw`) in separate processes for five 1,000,000-key workloads and three operations. Table cells show mean ± standard deviation, median, then min–max from the 10 timed runs, in milliseconds. Every timed command exited 0.

These are **whole CLI process times**, not isolated operation latency: each process generates the workload; `contains` then builds its representation and performs 8,192 probes (4,096 hits and 4,096 misses); `decode` builds then decodes. They include process startup and reporting. Criterion measurements isolate benchmark operations separately. This is an integer-set index comparison, not the byte-compression codec market matrix.

### Source-line evidence

The line-table profile attributes the level-mask loop in `src/lib.rs::build_level_masks` to 15 level builds over the 100,000-key input. The annotated source counts 7.0M instructions on parent-prefix selection, 4.4M on digit extraction, and 11.7M on mask updates. This confirms repeated full input scans at each emitted level as a major instruction cost. The codec width/depth is capped at 16, so the asymptotic build remains O(N) for fixed-width keys; the practical profile is roughly 15 passes here. This is an optimization target, not a measured before/after win. A fused one-pass builder would need to preserve byte-identical L1 images and would trade rereads for multiple mask streams/writes, so it must be A/B tested before retaining.

### Interpretation limits

Callgrind cache events are simulated, not hardware PMU counts, and instruction counts are not nanoseconds. Massif is process-wide: the observed peak includes the Rust CLI/runtime and workload construction, so it does not establish codec-only peak scratch. Hyperfine values above are whole CLI process timings. The latest Criterion benchmark job was still running when this report was assembled; check the workflow before citing Criterion results from this run.
